# tv

Телепрограмма двадцати эфирных каналов без рекламы и телеметрии.

Прод: `tv.nazarukroman.ru` · образ: `ghcr.io/nazarukroman/tv`

## Зачем

`tv.mail.ru` отдаёт на одни сутки сетки 717 КБ HTML плюс 508 КБ Google Tag
Manager, ходит в `apptracer`, `xray.mail.ru`, `mradx` и детектит адблок —
2.93 МБ в 60 запросах. Здесь та же задача решается примерно в 1/200 веса:
15 КБ на страницу дня, ноль стороннего кода.

## Главное ограничение: страница уже готова к моменту запроса

Страницы рендерятся, **сворачиваются** и сжимаются в момент **загрузки
данных**, а не запроса, и лежат в памяти в трёх кодировках. На запрос
приходится `Map.get` плюс запись готовых байтов — ни SQL, ни шаблонизатора на
горячем пути. Поиск подчиняется тому же правилу: индекс заголовков собирается
рядом со страницами, поэтому запрос — это скан массива, который уже в памяти.

Отсюда же следует главное свойство: **недоступность источника не влияет на
доступность сайта**. Холодный старт при мёртвом фиде отдаёт последнюю
сохранённую сетку.

## Источник данных

Официального API телепрограммы у российских вещателей нет — проверено:
`1tv.ru/api/v2/schedule` и `smotrim.ru/api/schedule` отдают 403 боту,
`tnt-online.ru/api/schedule` — 404, `ctc.ru` закрыт анти-ботом. Поэтому берётся
публикуемый XMLTV-файл, а не чужой внутренний XHR.

|          |                                                                               |
| -------- | ----------------------------------------------------------------------------- |
| Основной | `https://cdn.epg.one/ru.xml.gz` — 25 МБ, окно D-8…D+6, время уже `+0300`      |
| Запасной | `https://epg.iptvx.one/epg_noarch.xml.gz` — читаемые слаги вместо числовых id |

Из фида берутся только `start`, `stop`, `title`, `channel` и необязательный
`desc`. Жанры, постеры, актёры не нужны и не собираются.

**У каждого фида свои id, и это не деталь.** epg.one — непрозрачные числа
(`146` — Первый), iptvx.one — слаги, и слаги **не наши**: `five` там
`5kanal-ru`, `tvc` — `tvcentr`, `domashniy` — `domashny`, `matchtv` —
`match-tv`. Вывести одни из других нельзя, поэтому пин на каждый канал в каждом
фиде лежит в `config/channels.ts` и типизирован через весь union `SourceName`:
незаполненный id — это ошибка сборки, а не пустая колонка.

Измерено на живых фидах после отсечки хранения, по нашим двадцати каналам:

|           | передач | дней | скачивание |
| --------- | ------- | ---- | ---------- |
| epg.one   | 4739    | 10   | 43 с       |
| iptvx.one | 3863    | 8    | 85 с       |

## Ловушки, за которые уже заплачено

- **id у epg.one — непрозрачные числа без гарантий.** `146` — Первый, `353` —
  ТНТ. На каждом прогоне проверяется, что id всё ещё резолвится в ожидаемое
  имя **в том фиде, который читается**; иначе прогон падает громко, а не отдаёт
  пустую колонку.
- **Одна карта id на все источники — это неработающий фолбэк.** Так и было:
  `SOURCE_ID_TO_SLUG` строилась из чисел epg.one и отдавалась любому фиду, а
  `assertChannels` требовала все двадцать чисел от iptvx.one, где id — слаги.
  Резервный источник не мог резолвить ни одного канала **ни при каких
  обстоятельствах**, падал на всех двадцати и уносил прогон. Проверялось это
  ровно тогда, когда основной уже лежал, — то есть никогда до инцидента.
  Теперь id пинятся по источнику, а `sourceIndex(source)` строит карту под
  конкретный фид.
- **Сравнивать имена точной строкой нельзя.** Замерено на двух сборках одного
  фида с разницей в часы: набор алиасов у id 146 сменился с девяти во главе с
  «Первый канал» на семь во главе с «Первый FHD», без голого имени вообще.
  У НТВ есть только «НТВ HD»; в iptvx.one Матч ТВ идёт как «Матч!». Отсюда
  `lib/channel-name.ts` — нормализация регистра, `HD`/`FHD`/`orig`, сдвигов
  `+4` и регионов в скобках.
- **Декорация с цифрой снимается раньше, чем цифры разносятся пробелами.**
  `4k` лежал в множестве токенов, а фильтр по нему работает уже после
  `replace(/(\d+)/g, ' $1 ')` — то есть видел `4` и `k` и не срабатывал
  никогда. `Матч ТВ 4K` нормализовался в `матч тв 4 k` и не совпадал с
  `Матч ТВ`. Теперь такие маркеры (`4k`, `50`) снимаются регуляркой рядом с
  `TIMESHIFT`, а чисто буквенные (`hd`, `orig`) — по-прежнему фильтром токенов.
- **304 честен только про свой источник.** Если сетка собрана из резервного
  фида, «твоя копия моего файла актуальна» от основного — правда и бесполезная
  одновременно: она удержала бы резервную сетку ровно до тех пор, пока файл
  основного не меняется, то есть именно тогда, когда основной вернулся.
  Валидаторы отправляются, только если `provenance(db).source` — это тот же
  источник.
- **Один таймаут на весь обмен рвёт здоровую загрузку.** 60 секунд покрывали и
  соединение, и 25 МБ тела: epg.one укладывается в 43 с, а iptvx.one качается
  85 с — и обрывался посреди потока, что снаружи выглядело как «источник
  недоступен». Теперь два бюджета: 20 с на заголовки (мёртвый хост должен
  освободить очередь фолбэку быстро) и 10 минут на тело, причём второй
  снимается концом самого потока.
- **Фид отдаёт `Cache-Control: max-age=16070400`** — 186 дней. Без
  `Cache-Control: no-cache` в запросе любой прозрачный кэш вправе полгода
  отдавать старую копию, и снаружи это выглядит как «источник умер».
- **Логотипы каналов у источника идут по plaintext `http`** — прямая ссылка со
  страницы была бы заблокирована как mixed content.
- **`bun:sqlite` со `strict: true` привязывает параметры без `$`.** SQL
  сохраняет `$name`, объект передаёт `name`.
- **Московское время считается арифметикой, а не библиотекой.** MSK
  фиксирован UTC+3 без перехода на летнее время с 2014 года, метки в фиде уже
  `+0300`. Конвертация в UTC и обратно — единственный способ внести здесь баг.
- **`defer` на инлайновом `<script>` спецификацией игнорируется.** Прошлая
  версия страницы так и работала: замер показал firstPaint 240 мс _после_
  domInteractive 222 мс, то есть клиентский скрипт выполнялся до первого
  пикселя. Отложенность даёт `type="module"`, а не атрибут `defer`.
- **CSS `order` на мобиле ломает доступность.** Сетка на телефоне — одна
  колонка, и `order` оставляет порядок чтения и обхода табом не совпадающим с
  тем, что на экране. Это WCAG 1.3.2 и 2.4.3. Порядок задаётся перестановкой
  DOM; `order` используется только как временная мера до первой отрисовки.
- **Всё, что появляется после первой отрисовки, — это CLS.** Поле поиска и
  полоса «Сейчас в эфире» когда-то раскрывались скриптом: замер на холодной
  Slow 4G дал **0.19**, потому что сетка уезжала вниз на 171 пиксель через
  полсекунды после появления. Теперь контролы лежат в разметке и прячутся
  отсутствием `html.js`, а под полосу место резервируется классом `html.today`,
  который ставит boot.
- **302 с `/` стоит целого круга.** Документ не начинает грузиться, пока
  редирект не завершился: 575 мс на мобильном профиле, почти половина LCP, и
  именно на том URL, который набирают руками. `/` отдаёт сегодняшний день
  напрямую, а `<link rel=canonical>` оставляет каноническим адрес с датой.
- **Boot не может узнать день из URL.** `/` отдаёт сегодня, когда сегодня есть,
  и последний сохранённый день, когда его нет, — поэтому «в пути нет даты»
  значило «сегодня» и на холодном старте по протухшим данным врало: страница
  резервировала место под полосу «Сейчас в эфире», а приложение потом её
  убирало, сдвигая всю сетку на ~150 px уже после первой отрисовки. День
  читается из `<link rel=canonical>` — парсер видит его раньше, чем boot.
- **Передача, идущая через полночь, принадлежит вчера.** Она подшивается под
  день своего **начала**, поэтому запрос `WHERE day = $day` оставлял верх каждой
  колонки пустым, пока она идёт: ни одной строки `data-live`, ни одной карточки
  в полосе — каждую ночь, первые час-полтора суток. `programmesForDay` отдаёт
  день плюс то, что не закончилось к его началу; перенесённая строка сохраняет
  свой `day`, и по нему поисковый индекс её не дублирует.
- **Хэш во фрагменте должен нести канал.** На обычных сутках около девятисот
  пар (день, начало) делят от двух до тринадцати каналов, поэтому ссылка вида
  `#s<время>` открывала не ту передачу — первую попавшуюся в порядке вещания.
  Формат — `#<slug>-<время>`.

## Как устроено

```

  lib/xmltv.ts         потоковый разбор: ~465 000 элементов входит, ~7 500 остаётся
  lib/channel-name.ts  нормализация имён для проверки привязки id
  lib/fetch.ts         условный запрос (ETag/304), два таймаута, потоковая распаковка gzip
  lib/time.ts          московское время
  lib/labels.ts        даты по-русски — общие для рендерера и браузера
  lib/schedule.ts      что идёт сейчас, вокруг чего сворачивать колонку
  db/schema.ts         миграции, WAL, синхронизация списка каналов
  db/store.ts          транзакционная подмена дня, запросы, журнал прогонов, провенанс
  render/styles.css    вся таблица стилей, минифицируется в сборке
  render/bundle.ts     Bun.build клиента и стилей на старте процесса
  render/page.ts       HTML одного дня
  client/boot.ts       инлайн в <head>: порядок каналов до первой отрисовки
  client/app.ts        всё остальное, внешним модулем
  client/favourites.ts чистая логика списка избранного: порядок, не фильтр
  client/storage.ts    localStorage, который не умеет бросать
  client/search.ts     поиск по всем дням
  ingest.ts            один прогон загрузки
  server.ts            отдача готовых страниц, индекс поиска
```

### Фолбэк, который действительно работает

Проверено сквозным прогоном по живым фидам: основной отвечает 404 → резервный
даёт 3862 передачи по **двадцати из двадцати** каналов; основной возвращается →
перехватывает и переписывает сетку.

Три вещи, без которых это остаётся декорацией:

1. **id пинятся по источнику**, и тип требует заполнить их для каждого фида из
   `SOURCE_NAMES`. Третий источник не соберётся, пока не проставлены все двадцать.
2. **Порог `MIN_PROGRAMMES` — на источник.** Общий порог пришлось бы ставить
   либо слишком низким для основного, либо слишком высоким для резервного, а
   вторая ошибка отвергает фолбэк ровно тогда, когда он единственное, что есть.
3. **Провенанс хранится и показывается.** `provenance(db)` отвечает на два
   разных вопроса — _чьё_ тело записано последним (304 его не меняет) и _когда_
   в последний раз подтвердили актуальность (304 считается). Первый идёт в
   баннер «Данные из резервного источника», второй — в футер «Обновлено».
   Раньше в футере стояло время сборки снапшота и захардкоженный `epg.one`:
   перезапуск контейнера по трёхдневным данным печатал под ними текущее время.

### Сегодня живёт по адресу `/`

Дат-урлы остаются: страница дня — отдельно закэшированный и сжатый документ,
вкладки дней — обычные ссылки, а результат поиска обязан указывать на конкретную
передачу конкретного дня. Плохи они одним — их сохраняют в закладки. Человек
заходит на `/`, кликает четверг, сохраняет — и получает четверг навсегда.

Поэтому у сегодняшнего дня один адрес, а не два, и делает это браузер: сервер
при рендере не знает, какая из его вкладок сегодняшняя, потому что страницы
пересобираются дважды в сутки и одна из сборок переживает полночь.

- вкладка сегодняшнего дня получает `href="/"`;
- если день на экране — сегодня, а в адресной строке дата, она переписывается
  `replaceState` на `/` вместе с хэшем. Ни навигации, ни запроса: байты по
  `/day/<сегодня>` и по `/` — один и тот же документ, что закреплено тестом.

С выключенным JS не происходит ничего, и все ссылки остаются рабочими датами —
поэтому сервер рендерит именно их.

### Транзакция удаляет только то, что тут же заполняет

Подмена идёт по паре (канал, день) и только для тех пар, что реально пришли в
этом прогоне. Если фид молча потеряет канал, его вчерашние строки останутся на
месте, а не превратятся в пустую колонку.

Плюс порог `MIN_PROGRAMMES`: прогон, вернувший подозрительно мало, отклоняется
целиком. Оборванная передача приходит как валидный короткий документ.

### Клиент — это модули, а не строковый литерал

Раньше скрипты лежали строками в `render/`. Дёшево и дорого: `tsc` внутрь не
смотрел, линтер не смотрел, тест не мог импортировать, а переименование слуга в
`config/channels.ts` рассинхронизировало селекторы молча. Теперь это обычные
модули под `src/client/`, а `render/bundle.ts` собирает их через `Bun.build`
**на старте процесса** — так в Dockerfile по-прежнему нет шага сборки и нет
артефактов, которые надо держать в синхроне.

Типы проверяются двумя проектами: `tsconfig.json` — сервер (без DOM),
`tsconfig.client.json` — браузер (без `Bun`). Случайный `document` в серверном
коде и `process.env` в клиентском падают на проверке, а не в проде.

Список каналов подставляется в бандл через `define`, а не читается из разметки:
boot-скрипту он нужен раньше, чем существует хоть один элемент, — чтобы
отличить протухший слуг в `localStorage` от настоящего. Без этой проверки
удалённый канал занял бы позицию в порядке, которой не соответствует ни одна
колонка, и остальное избранное съехало бы на строку вниз.

### Два скрипта, и разница между ними принципиальна

`boot` инлайнится в `<head>` и блокирует парсер намеренно: он поднимает наверх
отмеченные каналы этого посетителя, в его порядке, **до первой отрисовки**.
Любой более поздний момент — это двадцать колонок, которые на глазах
перестраиваются. Круглый рейс здесь недопустим, поэтому инлайн.

`app` — внешний модуль, и внешний именно потому, что он побайтово одинаков на
всех пятнадцати страницах дней, а вкладки дней — обычные ссылки. Инлайн
пересылал бы 4 КБ на каждый открытый день. Адресуется хэшем содержимого и
кэшируется на год.

### Избранное — это порядок, а не фильтр

Все двадцать каналов на странице всегда. Звезда в заголовке колонки поднимает
канал наверх и больше не делает ничего: не прячет остальные, не открывает
диалог, не требует запроса. По умолчанию отмечены ТНТ и Матч ТВ.

Из этого следует несколько вещей, каждая из которых раньше стоила кода:

- **Пустое избранное — законное состояние.** Раньше пустой список означал
  пустую страницу, поэтому `normaliseFavourites` подменял его дефолтом, диалог
  запрещал снять последнюю галочку, а обработчик звезды молча игнорировал
  клик — три отдельные защиты от одного и того же. Теперь снять всё можно, и
  это просто порядок вещания.
- **Результат поиска ведёт куда угодно.** Атрибут `data-revealed` и правило
  `display:flex !important` существовали только затем, чтобы показать колонку,
  которую посетитель не выбрал. Показывать больше нечего.
- **Модалок нет вообще.** `client/picker.ts` и весь блок стилей `dialog` /
  `.pick-*` удалены; управление каналами живёт в той же сетке, которую человек
  и так читает.

Механика двух шагов осталась, потому что она про первую отрисовку, а не про
скрытие. Boot пишет `order` — отрицательный, от `-n` до `-1`, чтобы невыбранные
колонки остались на своём `order: 0` и не потребовали ни одного правила. После
отрисовки `app` переставляет колонки в DOM по-настоящему и `order` убирает:
картинка не меняется ни на пиксель, а порядок чтения и обхода табом перестаёт
врать. Переставляются при этом только те колонки, что реально сдвинулись, —
перевставка узла снимает с него фокус, и «переприслать все двадцать» стоило бы
фокуса на каждом нажатии звезды.

Порядок один и тот же в сетке и в полосе «Сейчас в эфире», обе зовут
`favouritesFirst` — двух копий правила «избранные первыми» не бывает долго.

Прежний выигрыш сохраняется целиком: одна закэшированная страница обслуживает
любую раскладку, переключение избранного не стоит ни одного запроса, а с
выключенным JS видно те же двадцать каналов — просто в порядке вещания.

### Колонка приходит уже свёрнутой

Двадцать развёрнутых каналов на телефоне — документ высотой 21 500 пикселей.
Колонка показывает три строки: якорь и то, что за ним.

Якорь выбирает `lib/schedule.ts`, и его использует и рендерер, и браузер. Что
идёт в эфире — побеждает. Всё остальное (день ещё не начался, день кончился,
разрыв в сетке, и сервер, у которого часов нет вовсе, потому что документ один
на всех) откатывается к началу прайм-тайма. Это лучше первой строки суток:
никто не открывает телепрограмму, чтобы узнать, что шло в десять минут первого.

Отсюда — почему сворачивает **сервер**, а не клиент. Если бы сворачивал клиент,
браузер отрисовал бы весь день и потом свернул его: сдвиг вёрстки величиной в
несколько экранов, на том самом телефоне. А так три строки сменяются тремя
другими, и страница почти не движется. Правило свёртки закрыто селектором
`html.js`, который ставит boot: без JS развернуть обратно было бы нечем, значит
и сворачивать нечего.

**«Показать все» — чекбокс, а не кнопка**, и это единственный контрол, который
что-то прячет. Хэшированный ассет отдаёт 404 те пять минут, пока закэшированная
страница переживает деплой, а второй запрос на мобильной сети падает буднично.
Ни то, ни другое не имеет права оставить человека перед тремя строками из
двадцати семи без единого способа увидеть остальные. Поэтому развернуть колонку
умеет CSS, а `app.ts` только ставит галочку, когда ведёт по результату поиска.

Тот же 404 закрыт и со стороны сервера: `/app.<hash>.js` отдаёт текущий бандл на
**любой** хэш, просто без `immutable`, если хэш не совпал.

### Цвет — это четыре числа на тему

У канала есть только hue (`--h`), лежит в разметке. Светлоту и цветность даёт
тема, а сам цвет собирает CSS. Поэтому переключение в тёмную меняет четыре
числа, а не сорок, и новый канал не требует ни строки CSS. Hue раздаются по
позиции в списке, а не подбираются: это метки различения, а не бренд-цвета —
шесть из этих вещателей используют примерно один красный.

### Кнопки прайм-тайма больше нет

Была: чекбокс `#prime`, прятавший всё, что не попадает в 18:00–24:00. Убрана
вместе с атрибутом `data-prime` на каждой строке (630 штук на сутки — чистая
энтропия в сжатом потоке) и с условием `:not(:has(#prime:checked))`, которым
были закрыты правила свёртки, чтобы три состояния не спорили за приоритет.

Само прайм-время осталось там, где оно и работало: `windowAnchor` сворачивает
колонку вокруг 18:00, когда часов нет или в эфире ничего нет. Это не фильтр,
а догадка о том, какие три строки показать, — и её видно на каждой странице.

Остался один контрол, чью работу целиком делает CSS: `.unfold` у каждой
колонки, через `:has()`. Работает с выключенным JS, не стоит ничего в рантайме
и — главное — переживает ситуацию, когда бандл не пришёл.

### Шапка на телефоне не липкая

Три её ряда — это 128 px на сегодняшнем дне и 99 px на остальных (строки часов
там нет), 15% экрана 844 px. Подняться за поиском почти бесплатно, а шестая
часть экрана возвращается расписанию. Липкими остаются заголовки каналов —
теряешь в чтении именно их. На широких экранах вертикали хватает, и шапка
остаётся на месте.

### Поиск живёт на сервере

Тот же корпус, отданный в браузер, — около 74 КБ gzip на пятнадцатидневном
окне, впятеро больше всей страницы. Ответ из памяти сервера стоит доли
миллисекунды и ноль байт, пока никто не печатает. Индекс собирается в
`buildSnapshot` вместе со страницами, так что запрос — не обращение к базе.

`ё` и `е` складываются с обеих сторон: фид непоследователен, а в письме `ё`
факультативна.

## Что это дало, и чего не дало

Замерено на реальном дне (2026-08-27, 630 передач, 20 каналов), мобильный
профиль 390×844×3, CPU ×4, Slow 4G, кэш выключен, по три прогона.

**По байтам это почти размен, а не победа.** Решётка ушла, но её место занял
клиентский бандл, и на первом визите они примерно гасят друг друга:

|                                 | было          | стало            |
| ------------------------------- | ------------- | ---------------- |
| Отдавалось на самом деле        | 23 039 (gzip) | 19 881 (br) −14% |
| Повторный визит, смена дня      | 23 039        | 15 615 −32%      |
| При равном сжатии, первый визит | 17 014 (br)   | 19 881 **+17%**  |
| При равном сжатии, повторный    | 17 014        | 15 615 −8%       |

Честно: половина «выигрыша по весу» в первой строке — это переход с gzip на
brotli, а не редизайн. Настоящий выигрыш в весе — только на повторных визитах,
и он реален, потому что вкладки дней это обычные ссылки, а бандл кэшируется на
год.

**Выигрыш там, где его видно:**

|                            | было             | стало    |
| -------------------------- | ---------------- | -------- |
| Горизонтальная прокрутка   | **есть** (2.05×) | нет      |
| Высота документа           | 9 465 px         | 1 772 px |
| Узлов, требующих раскладки | все 630 строк    | 18       |
| CLS, холодная загрузка     | 0.00             | 0.00     |
| Forced reflow в трейсе     | есть             | нет      |

**И одна честная регрессия: LCP 310 мс → 420 мс.** LCP-элементом стал заголовок
в карточке «Сейчас в эфире», а её рисует клиент — раньше им была ячейка сетки,
приезжавшая с сервера. FCP при этом не изменился (~230 мс): сама сетка видна
ровно так же быстро. `modulepreload` отыграл около 60 мс из этой сотни;
остальное — круг до бандла. Уменьшать карточку, чтобы она перестала быть
LCP-элементом, — это подгонка метрики, а не ускорение, и мы так делать не стали.

### Чем оплачены двадцать каналов сразу

Замерено на том же дне (2026-08-27, 630 передач, 20 каналов) после перехода
на «избранное — это порядок»: байты — `curl`, точно; высота и число узлов —
390×844; CLS — трейс на том же профиле (Slow 4G, CPU ×4).

|                                 | 6 избранных из 20 | все 20   |
| ------------------------------- | ----------------- | -------- |
| Первый визит (br, док + бандл)  | 19 881            | 18 597   |
| Повторный визит, смена дня (br) | 15 615            | 15 189   |
| Высота документа                | 1 772 px          | 5 274 px |
| Узлов, требующих раскладки      | 18                | 60       |
| Горизонтальная прокрутка        | нет               | нет      |
| CLS, холодная загрузка          | 0.00              | 0.00     |
| Forced reflow в трейсе          | нет               | нет      |

Байты не выросли, а упали, хотя видно стало втрое больше: `data-prime` на
каждой из 630 строк, разметка и стили диалога и сам контрол прайм-тайма ушли —
а разметка колонок не менялась, она и раньше содержала все двадцать каналов,
CSS их только прятал. (642 строки вместо 630 — это передачи, переходящие через
полночь, которые теперь отдаются и следующему дню.)

Выросло ровно то, что и должно было: **высота документа втрое, 1 772 → 5 274 px
на телефоне.** Это цена решения, а не регрессия — двадцать свёрнутых колонок
против шести. Свёртка держит её на уровне шести экранов вместо 21 500 пикселей,
которые дал бы развёрнутый день, и раскладку по-прежнему считают 60 узлов, а не 630. Горизонтальной прокрутки нет, CLS остался нулевым.

Forced reflow, появившийся было в трейсе, стоил 53 мс: `scrollIntoView` на
вкладке дня читал раскладку между перестановкой колонок и записью атрибутов на
630 строк, и браузер считал её дважды. Порядок в `start()` теперь строгий —
сначала все записи, потом все чтения.

Сборка снапшота — 401 мс на десять дней, и она уступает поток раз в день
(`await` между днями): иначе каждый запрос, попавший на выкладку новых данных,
ждал бы её целиком, включая `/healthz`.

## Разработка

```bash
bun install
bun test
bun run typecheck        # два проекта: сервер и клиент
bunx oxfmt && bunx oxlint

TV_DB=./data/tv.db bun run src/ingest.ts   # загрузить
TV_DB=./data/tv.db bun run src/server.ts   # отдавать
TV_DB=./data/tv.db bun run src/main.ts     # и то и другое
```

Формат — `oxfmt` + `oxlint`, точки с запятой, одинарные кавычки, ширина 120.
Правило целиком: `~/.claude/skills/js-formatting/SKILL.md`.

## Переменные окружения

| Переменная | По умолчанию      | Смысл                                                                              |
| ---------- | ----------------- | ---------------------------------------------------------------------------------- |
| `TV_DB`    | `/app/data/tv.db` | Файл SQLite. Только локальный диск, никогда NFS: WAL нужен настоящий POSIX-locking |

Секретов у сервиса нет.

## Ручки

| Путь              | Что делает                                                                                           |
| ----------------- | ---------------------------------------------------------------------------------------------------- |
| `/`               | Сегодняшний день, без редиректа. **Адрес для закладки** — клиент приводит сюда URL сегодняшнего дня  |
| `/day/YYYY-MM-DD` | Страница дня. ETag, 304, brotli/gzip/identity по `Accept-Encoding`. Канонический адрес — всегда этот |
| `/search?q=`      | JSON, поиск по всем сохранённым дням. Меньше двух и больше ста символов — пустой ответ               |
| `/app.<hash>.js`  | Клиентский бандл. Совпал хэш — `immutable` на год, не совпал — текущий бандл на 5 мин                |
| `/healthz`        | 200 только если кэш страниц непуст — контейнер с пустой базой не считается здоровым                  |
| `/metrics`        | Prometheus: горизонт данных, число передач, время сборки, размер индекса поиска                      |

Ошибка в обработчике отдаёт 500 и строчку текста, а стек уходит в лог:
`development: false` выставлен явно, потому что по умолчанию Bun смотрит на
`NODE_ENV`, которого в контейнере нет, и отдал бы стек с путями наружу.

## Деплой

Образ собирается своим workflow и пинуется в homelab неизменяемым тегом
`sha-<commit>`. Renovate такой тег не бампит — обновлять вручную:

1. Дождаться сборки, взять короткий sha.
2. Поправить тег в `homelab/stacks/tv/compose.yaml`.
3. `make deploy stack=tv`.
